# חיבור iCloud ליומן המשמרות

שרת Firebase Functions מתחבר ל־CalDAV של Apple ויוצר בחשבון המשתמש יומן ייעודי בשם ״המשמרות שלי״. הוא שומר את כתובת החשבון ואת הסיסמה הייעודית מוצפנות יחד באמצעות AES-256-GCM. מפתח ההצפנה נמצא ב־Secret Manager. פונקציות החיבור דורשות משתמש Firebase מאומת.

## זמינות

גרסת האתר המתארחת בתוכנית Spark מציגה את מצב הזמינות בהגדרות. היא אינה מבקשת פרטי Apple. פריסה של Functions והמשימה המתוזמנת ב־Firebase דורשת תוכנית Blaze. ההגדרה `VITE_ICLOUD_SYNC_ENABLED=true` מיועדת לפרויקט שבו השירות נפרס. פיתוח דרך האמולטורים משתמש ב־`VITE_FIREBASE_EMULATORS=true`. [מידע על תוכניות Firebase](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans) · [הנחיות Apple לסיסמה ייעודית](https://support.apple.com/he-il/102654)

## מבנה

| קובץ | אחריות |
| --- | --- |
| `index.js` | כניסה מורשית, פרטי חיבור מוצפנים, נעילת סנכרון, החלטות המשתמש ותזמון |
| `caldav.js` | איתור שרת החשבון, יצירת יומן ייעודי, קריאה וכתיבה מותנית בגרסת המשאב |
| `events.js` | פענוח ויצירת iCalendar, השוואת גרסאות והצפנה |
| `sync.js` | סנכרון דו־כיווני, מחיקות, זיהוי חפיפות והגנה על משמרות שהושלמו |
| `test/calendar.test.js` | בדיקות מול תשובות CalDAV ומסד נתונים מדומים |
| `test/firestore-emulator.js` | בדיקת עסקאות אמיתיות באמולטור, אישור שינויים ובידוד משתמשים |

## התנהגות

- הסנכרון רץ מדי 15 דקות וזמין גם בכפתור ידני. בכל סבב נקראת רשימת ה־ETag של היומן הייעודי. תוכן אירוע נקרא כשהגרסה השתנתה. מזהה האירוע נשמר בעת עריכת הכותרת או השעות, כולל הזזה ליום אחר.
- אירוע חד־פעמי מתווסף כמשמרת מתוכננת. שעון נוכחות פתוח, אירועים ליום שלם וסדרות חוזרות אינם מיוצאים כמשמרות חדשות. במכשיר מוצג מספר האירועים שהיומן דילג עליהם. מלבד מזהי סנכרון וגרסאות, רק הכותרת, שעת ההתחלה ושעת הסיום מועברות לאפל. יומנים אחרים בחשבון אינם נסרקים.
- שינוי מקביל בשני הצדדים או שינוי ביומן Apple במשמרת שהושלמה ממתין להחלטה בהגדרות. שינויים ביומן שיוצרים חפיפת שעות או מוציאים הפסקה מטווח המשמרת ממתינים לתיקון. שינוי חדש לאחר הצגת ההחלטה מחייב בדיקה מחודשת.
- ניתוק מוחק את פרטי החיבור המוצפנים ומפסיק את הסנכרון. היומן ב־Apple והמשמרות שהוזנו נשארים בבעלות המשתמש.

## הרצה ובדיקה

הגרסה המיועדת להרצה בענן היא Node.js 22.

```sh
npm ci --prefix functions
npm test --prefix functions
```

להרצה מקומית, הגדירו את `APPLE_CALENDAR_ENCRYPTION_KEY` בקובץ `functions/.secret.local` לפי פורמט קובצי הסביבה. הערך הוא מפתח אקראי באורך 32 בתים בקידוד Base64. אפשר ליצור ערך עם `openssl rand -base64 32`. הקובץ מוחרג מ־Git. הפעילו את Functions, Auth ו־Firestore באמצעות Firebase Emulator Suite. לבדיקת העסקאות מול אמולטור Firestore פעיל בכתובת מקומית, הריצו `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 npm run test:emulator --prefix functions`. הבדיקה משתמשת במזהה הפרויקט `demo-shuon-apple`. הבדיקות האוטומטיות אינן משתמשות בחשבון Apple. חיבור בפועל מתוך האמולטור משתמש ב־iCloud אמיתי ויוצר יומן בחשבון שנבחר.

בסביבת ענן מורשית יש להגדיר את אותו שם הסוד ב־Firebase Secret Manager. החלפת המפתח דורשת הצפנה מחדש של הרשומות הפעילות או חיבור החשבונות מחדש. פרטי החיבור, מטא־נתוני הגרסאות והמחיקות זמינים לשרת בלבד. הגישה לנתוני המשתמש מתבצעת תחת `users/{uid}/shifts`. [תיעוד הסודות של Firebase](https://firebase.google.com/docs/functions/config-env#secret_parameters)
