# חיבור שועון ליומן Apple

שועון משתמש ב־CalDAV כדי להציג את הלוחות הזמינים לכתיבה בחשבון iCloud ולסנכרן משמרות. לאחר אישור המשתמש, פרטי החיבור מוצפנים ב־AES-256-GCM עם שיוך לחשבון Firebase שלו. ניתוק מוחק אותם. אפשר גם לבטל את הסיסמה הייעודית דרך חשבון Apple. [הנחיות Apple](https://support.apple.com/he-il/102654)

## הפעלה ב־Firebase Spark וב־Netlify Free

האתר, ההזדהות ונתוני המשמרות נשארים ב־Firebase. מקשרים פרויקט Netlify נפרד למאגר ובוחרים במסלול Free מבוסס קרדיטים. הגדרות הבנייה והפונקציות נמצאות ב־`netlify.toml`. המשתמשים נכנסים לשועון כרגיל.

1. מגדירים בסודות סביבת הייצור של הפונקציות ב־Netlify את `FIREBASE_SERVICE_ACCOUNT_JSON` עם חשבון שירות של פרויקט Firebase בעל הרשאת קריאה וכתיבה ב־Firestore (למשל `roles/datastore.user`). השרת משתמש בו גם לאימות אסימוני Firebase ID של אותו פרויקט.
2. מגדירים `APPLE_CALENDAR_ENCRYPTION_KEY` כמפתח אקראי של 32 בתים בקידוד Base64. אפשר ליצור אותו עם `openssl rand -base64 32`. בחיבור מאותו שרת Firebase קודם יש להעביר את המפתח הקיים כדי לפענח חיבורים פעילים. שומרים את הסודות אצל ספק האירוח בלבד.
3. פורסים גרסת ייצור ב־Netlify. מוודאים שפונקציות ה־API ועבודת הרקע מופיעות בפריסה. פריסה זו אינה דורשת חיבור לחשבון Apple אישי של בעל האתר.
4. מגדירים את `VITE_APPLE_CALENDAR_API_URL` לכתובת ה־HTTPS של שירות Netlify בעת בניית האתר, מריצים `npm run build` בתיקיית הפרויקט ופורסים את התוצר ל־Firebase Hosting. השירות מתיר את שני דומייני Firebase של שועון כברירת מחדל. לדומיין נוסף מגדירים `CALENDAR_ALLOWED_ORIGINS` כרשימת מקורות מלאה המופרדת בפסיקים.
5. מתחברים לשועון ולחשבון iCloud לבדיקה, בוחרים לוח ומוסיפים משמרת עתידית. בודקים את שעות המשמרת ואת שדה ״זמן נסיעה״ באפליקציית היומן. משנים את האירוע ב־Apple, לוחצים על ״סנכרון עכשיו״ ובודקים שהמשמרת התעדכנה.

שינויים בשועון מסתנכרנים בשמירה. לשינויים שביצעתם ביומן Apple לחצו על ״סנכרון עכשיו״.

## מה מסתנכרן

- בלוח אישי שועון קורא תוכן של אירועים המשויכים למשמרותיו בלבד. אימות מזהה וגרסה מונע דריסה של פגישות פרטיות. בלוח ״המשמרות שלי״ גם אירוע חד־פעמי חדש יכול ליצור משמרת.
- זמן נסיעה נשמר כחלק מהאירוע בתכונת Apple. שינוי העדפה משפיע על משמרות עתידיות. שעות ההתחלה, הסיום והשכר ממשיכות להתבסס על המשמרת עצמה.
- שינוי בשני הצדדים או עריכת משמרת שהסתיימה ממתינים להחלטת המשתמש בהגדרות. חפיפות דורשות תיקון. אירועים חוזרים ואירועים ליום שלם מדולגים.

## מפת הקוד

| רכיב | אחריות |
| --- | --- |
| `netlify/`, `admin-app.js` | API מאומת, ושיגור משימות רקע |
| `service.js`, `caldav.js` | גילוי לוחות, בחירה, פרטי חיבור, נעילות ותקשורת עם Apple |
| `sync.js`, `events.js` | השוואה ויישוב שינויים, אירועי iCalendar וזמן נסיעה |
| `index.js` | מתאמי Firebase עבור האמולטורים ועבור פריסות Functions קיימות |
| `src/components/AppleCalendar*.tsx`, `src/lib/` בשורש הפרויקט | מדריך החיבור, דמו, הגדרות וקריאות לשירות |

## פיתוח ובדיקות

מריצים `npm ci --prefix functions` ואחריו `npm test --prefix functions`. בדיקות יחידה משתמשות בנתוני דוגמה. לבדיקת בידוד משתמשים ועסקאות אפשר להריץ `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 npm run test:emulator --prefix functions` מול אמולטור פעיל.

לבדיקת Firebase Functions מקומית משתמשים ב־`VITE_FIREBASE_EMULATORS=true`, בעותק פיתוח של מפתח ההצפנה בתוך `functions/.secret.local`, ובאמולטורים של Auth, Firestore ו־Functions. חיבור לחשבון Apple אמיתי דרך האמולטור כותב לאותו חשבון iCloud. הדמו ב־`/demo#settings` משתמש רק בנתוני דוגמה מקומיים.
